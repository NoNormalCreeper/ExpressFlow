# 作业要求摘要

## 题目一功能清单

- 用户注册和登录，用户信息需要长期保留。
- 登录后修改账户密码。
- 查询和充值用户账户余额。
- 用户发送快递到指定用户，系统分配快递单号，快递进入待签收状态，每件扣除 15 元并转入管理员账号。
- 收件用户查看未签收快递，并选择一个或多个快递签收。
- 用户查询自己发出和接收的快递，可按发送人/接收人、时间、快递单号查询。
- 管理员查看所有用户信息和历史快递详情，可按用户、时间、快递单号查询。

## 题目二新增内容

- 引入快递员角色，管理员可以添加和删除快递员。
- 登录时区分用户、快递员、管理员身份和权限。
- 快递分类至少包括易碎品、图书、普通快递。
- 按物品分类计算价格，物品基类需要虚函数 `getPrice()`。
- 快递状态扩展为待揽收、待签收、已签收。
- 管理员为待揽收快递分配快递员。
- 快递员揽收后，快递从待揽收变为待签收，并获得该快递费的 50%。
- 快递员可以查询自己揽收和投递的快递任务。

## 题目三新增内容

- 将物流管理平台改为传统 C/S 网络版。
- 客户端和服务器是不同进程。
- 客户端通过 socket 与服务器通信。
- 不使用 RPC 框架。
- 网络版功能要求与单机版一致，并支持一定错误场景处理。

## 课程硬性要求

- 三个题目必须分别提交程序，不能只提交最终网络版。
- 每个程序的代码只完成自身功能，三个程序体现逐步增强关系。
- 使用 C++ 和面向对象程序设计方法。
- 用户、管理员/物流公司、快递信息需要持久化，题目要求练习文件操作。
- 除 `main` 和必要友元函数外，不允许出现非类成员函数。
- 不改变对象状态的成员函数需要显式标注 `const`。
- 如使用友元函数，需要在代码和实验报告中说明不可替代性。
- 类的数据成员和成员函数声明、实现需要按课程要求加注释。
- 题目二需要物品继承体系和虚函数 `getPrice()`。
- 题目三必须使用 socket，不能使用 RPC 框架。
